SDN primer (5 minutes)

Software-defined networking (SDN) moves the decisions about forwarding out of individual switches and into software with a view of the whole network. You need three terms, the SDN planes:

PlaneWhat it doesExample
Data planeForwards each packet by looking it up in a table in the switch hardwareA switch matching a destination and sending the packet out port 3
Control planeDecides what goes into those tablesA routing protocol computing shortest paths
Management planeConfigures, monitors and upgrades the devicesAn operator pushing a config file, an alerting system

Traditional networks run the control plane on every switch. Each switch discovers its neighbors, exchanges routing messages with them (OSPF, IS-IS, BGP), builds its own picture of the network and computes its own tables. No device has the whole picture.

SDN, as OpenFlow defined it, splits the control plane off the switches. A logically centralized controller (it may be several replicated machines acting as one) holds the global view, computes the forwarding entries and installs them in each switch’s flow table over a dedicated channel, using the OpenFlow protocol. The switch keeps the data plane and becomes simple: match a packet against its flow table, apply the action, and ask the controller when nothing matches.

TraditionalSDN (OpenFlow)
Who knows the whole topology?Every switch, each building its own copyThe controller
Who computes the forwarding tables?Every switch, for itselfThe controller, for all switches
What travels from the control logic to a switch?Routing messages between neighborsReady-made flow table entries

Source: N. McKeown et al., “OpenFlow: Enabling Innovation in Campus Networks,” ACM SIGCOMM Computer Communication Review, 38(2), April 2008. The Jupiter paper cites it as reference 18.

Keep the second table in mind: Firepath does not fit neatly in either column.
