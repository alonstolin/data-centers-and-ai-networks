Why this matters in Jupiter

“Building a fabric with thousands of cables invariably leads to multiple cabling errors.” Google's answer was Neighbor Discovery (ND). Every switch is loaded with the same cluster config, so it knows which peer port should sit at the far end of each cable. ND checks what is really there and exchanges what it found with the peer. A port is declared up to the routing process only if it is both PHY up and ND up. (Section 5.2.1)

A problem counts as confirmed once switches on two different sides of it have labeled their ports correctly. When all five are confirmed, the fabric comes up.

How to pick a label

  • OK heard peer = plan, peer hears you: yes, errors below 1e-12
  • Miswired heard peer is a different port than the plan
  • One-way you hear the peer but peer hears you: no
  • High errors plan and peer match, but the error rate is high
  • Link down PHY is DOWN: there is no working cable
  • Peer silent PHY is up but you hear nothing from the peer (discovered -)

PHY is the physical link. ND is the neighbor check each switch runs on every port. A port is only usable when it is PHY up and ND up. Some problems cannot be seen from one switch alone, so check the shared map too.
